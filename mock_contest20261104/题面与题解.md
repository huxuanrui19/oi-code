## T1 排列 `arrange`

原题：P7972，KSN2021 Self Permutation。原题时间限制 2 秒，空间限制 256 MB，满分为 100 分。

### 题面

给定一个长度为 `n` 的排列 `a`。每次可以选择两个相邻的数，删除其中较大的那个。

删除后，左右两部分会拼接起来，原来不相邻的数可能因此变得相邻。问进行若干次操作后，最终可能得到多少种不同的非空序列。答案对 `1e9+7` 取模。

### 输入格式

第一行一个整数 `n`。

第二行 `n` 个整数，表示排列 `a`。

### 输出格式

输出一个整数，表示最终可能得到的序列数量模 `1e9+7`。

### 数据范围

对于全部数据，`1≤n≤3×10^5`，`a` 是 `1...n` 的排列。

原题有特殊小样例、`n≤200` 等部分分；这里重点写可递进的通用做法，而不是只针对某一个固定样例。

### 原题样例

#### 样例 1

输入：

```text
3
2 3 1
```

输出：

```text
3
```

三种结果为 `[2,3,1]`、`[2,1]`、`[1]`。

#### 样例 2

输入：

```text
4
2 1 4 3
```

输出：

```text
6
```

### 部分分一：枚举保留集合

`n` 很小时，可以枚举最终保留哪些位置，再检查中间被删去的数是否真的能删干净。

因为原数组是排列，不同保留位置对应不同序列，不需要再去重。直接枚举所有子集需要 `O(2^n)` 个状态，检查一个状态还需要 `O(n)`，只适合非常小的数据。

这个做法的价值是：可以把“操作过程”转化为“保留下来的子序列是否合法”。

### 部分分二：按结尾做 DP

设 `f[i]` 表示以原位置 `i` 结尾的合法序列数量。这里的“合法”只要求 `i` 之前的数能按规则处理，暂不删除 `i` 后面的后缀。

如果序列只保留 `i`，那么 `i` 前面的所有数必须能删空；否则设倒数第二个保留位置为 `j`，需要先删空 `(j,i)`，再把前面的合法序列接到 `a[i]` 后面。

核心判定如下。

> 对 `l<r`，`(l,r)` 中的数能被全部删除、同时保留 `a[l]` 和 `a[r]`，当且仅当
>
> `min(a[l],a[l+1],...,a[r]) = min(a[l],a[r])`。

原因是：

- 如果中间有数比两个端点的较小值还小，它不可能被端点删除；要删它，只能保留一个比它更小的数，但区间内没有这样的数；
- 如果最小值就是某个端点，那么另一个端点及中间较大的数都可以按从大到小的顺序被较小值删除。

因此有转移：

```text
f[i] = 单独保留 i 的方案数
     + 所有满足 (j,i) 可删空的 f[j] 之和
```

直接枚举 `j` 并维护区间最小值，复杂度 `O(n^2)`；若每个区间都重新求最小值，则是 `O(n^3)`。`O(n^2)` 已能处理 `n≤200` 的部分分。

最后，只有 `a[i]` 是后缀最小值时，`i` 后面的数才能全部删除，所以答案是所有后缀最小值位置上的 `f[i]` 之和。

### 满分做法：用前驱、后继重写转移条件

直接枚举 `j` 的瓶颈是判断 `(j,i)` 能否删空。定义：

```text
pre[i] = i 左边最近的、数值小于 a[i] 的位置；不存在则为 0
nxt[i] = i 右边最近的、数值小于 a[i] 的位置；不存在则为 n+1
```

由于输入是排列，不存在相等值。

对于 `j<i`，可以把转移条件统一写成：

```text
nxt[j] > pre[i]
```

分两种情况理解：

1. `a[j]>a[i]`：中间不能出现小于 `a[i]` 的数，所以 `j` 必须位于 `pre[i]` 右边；这等价于 `nxt[j]>pre[i]`。
2. `a[j]<a[i]`：中间不能出现小于 `a[j]` 的数，所以 `nxt[j]≥i`。而 `pre[i]<i`，这同样包含在 `nxt[j]>pre[i]` 中；反过来，若 `nxt[j]` 落在 `pre[i]` 和 `i` 之间，它也会成为 `i` 左边更近的较小值，矛盾。

于是：

```text
f[i] = 所有满足 j<i 且 nxt[j]>pre[i] 的 f[j] 之和
```

再加上“一个数也不保留在 `i` 前面”的空序列方案。

按 `i` 从小到大扫描时，把每个 `f[j]` 加到树状数组下标 `nxt[j]-1`。查询 `pre[i]+1...n` 的和，就恰好得到所有 `nxt[j]>pre[i]` 的 DP 值。

空序列可以看成初值 `1`，只放在树状数组下标 `1`：当 `pre[i]=0` 时它会被统计，否则会被减去。

树状数组维护的是 DP 值的前缀和，不是原数组数值的和。模意义下的区间和写成：

```text
(sum(n) - sum(pre[i]) + mod) % mod
```

### 正确性概括

1. 最终序列一定是原排列的子序列；两个保留位置之间的所有数必须满足区间最小值条件。
2. `f[i]` 枚举倒数第二个保留位置，因此不重不漏地统计所有以 `i` 结尾的合法前缀序列。
3. 前驱、后继条件与区间最小值条件等价，树状数组只是快速求满足条件的 `f[j]` 之和。
4. 答案只统计后缀最小值位置，恰好对应后缀也能删空的情况。

### 复杂度

- 求 `pre`、`nxt`：各 `O(n log n)`；
- DP：`O(n log n)`；
- 空间：`O(n)`。

整理版沿用了赛时代码的树状数组思路，但拆清了函数、补全变量含义，并保留 `dp` 数组用于最后统计答案。

- 赛方原始代码：`arrange/source.cpp`，使用 `set` 维护递减结构；

## T2 单词 `word`

本场题号 G123920。暂未找到可以可靠对应的原题，以下题面来自本场截图，不猜原题题号。

### 题面

字符集由小写英文字母和 `?` 组成。两个等长字符串相似，当且仅当可以把两个串中的每个 `?` 独立替换成任意小写字母，使替换后的两个字符串完全相同。

例如，`a???` 和 `?b?a` 都可以替换成 `abba`，所以它们相似。

给定 `n` 个长度为 `m` 的字符串，求相似的无序字符串对数。同一对只计算一次；输入中可能出现完全相同的字符串。

### 输入格式

第一行两个整数 `n,m`。

接下来 `n` 行，每行一个长度为 `m` 的字符串。

### 输出格式

输出相似字符串的无序对数。

### 数据范围说明

截图没有给出正式的数据范围和分档表。附件三组数据的 `m` 分别为 `2、4、6`，`n` 最大为 `42345`。

赛方 std 使用 30 进制把长度为 `m` 的模式压入 `long long`，因此沿用该编码时还需保证 `30^m` 不发生 64 位溢出。整理版与赛方 std 使用同一数据假设。

### 自测例

输入：

```text
4 2
a?
?b
ab
cc
```

输出：

```text
3
```

三对为 `(a?, ?b)`、`(a?, ab)`、`(?b, ab)`。这不是附件中的官方样例，只是帮助理解题意的小例子。

### 部分分：两两直接检查

两个字符串相似，当且仅当每个位置都满足下面至少一个条件：

```text
s[k] == '?'
t[k] == '?'
s[k] == t[k]
```

逐对枚举并扫描每一位即可。时间复杂度 `O(n^2*m)`，空间复杂度 `O(n*m)` 或边读边存时的 `O(n*m)`。

这个判断也说明：不需要真的枚举 `?` 的替换字母。两个串能否变得相同，只与每个位置的兼容关系有关。

### 赛时 Trie 做法及其瓶颈

赛时代码建立 27 叉 Trie：26 个小写字母加一个 `?` 分支。依次插入前串、查询当前串，可以正确处理重复串，并且每个无序对只统计一次。

查询时：

- 当前字符为字母：可走相同字母边，也可走对方的 `?` 边；
- 当前字符为 `?`：可走对方的 `?` 边，也可走 26 条字母边。

它的逻辑是正确的，但最坏情况下，每次查询可能遍历 Trie 的大量结点。例如很多字符串都含大量 `?` 时，单串查询就不能视为只走 `O(m)` 条边。因此不能把它直接写成有保证的满分复杂度。

### 满分做法：把“是否兼容”变成“模式是否有交集”

逐对检查慢的原因是同一个串被反复比较。可以把每个串预先展开成若干模式键，再用哈希表统计相同键。

代码使用 `0...25` 表示原字母，并增加两个标记：

- `26`：插入串此处是字母，查询串此处是 `?`；
- `27`：插入串此处是 `?`。

对**要插入哈希表的串 `s`**：

```text
字母 c -> c 或 26
?      -> 27
```

对**正在查询的串 `t`**：

```text
字母 c -> c 或 27
?      -> 26 或 27
```

两个串在某个位置兼容，当且仅当它们在该位置有共同的模式符号；所有位置都兼容，当且仅当它们至少有一个完整模式键相同。

逐项验证：

- 两边为相同字母：键 `c` 相遇；
- 两边为不同字母：没有共同键；
- 插入为字母、查询为 `?`：键 `26` 相遇；
- 插入为 `?`、查询为字母：键 `27` 相遇；
- 两边都是 `?`：键 `27` 相遇。

这里 `26` 和 `27` 的含义不对称，正是为了避免两个不同字母被误判为兼容。

因此每个字母位置在插入和查询时各有两种选择，每个字符串最多产生 `2^m` 个键。

依次处理输入：先查询之前字符串建立的哈希表，再插入当前字符串，保证只统计 `j<i` 的无序对。

### 复杂度

令每个串最多生成 `2^m` 个键：

- 时间复杂度 `O(n*2^m)`，哈希表按均摊常数查询；
- 空间复杂度 `O(n*2^m)`，实际取决于不同模式键的数量；
- 答案最大为 `n(n-1)/2`，必须使用 64 位整数。

### 代码文件

- 我的赛时代码：`word/contest.cpp`；
- 赛方原始代码：`word/source.cpp`；
- 整理版：`word/solution.cpp`，使用 `unordered_map<long long,int>` 计数。

## T3 网格图 `grid`

本场题号 G123921。暂未找到可靠原题；赛方 std 中使用的外文文件名是 `cake`。

### 题面

有一张 `R` 行 `C` 列的网格图，每个格子被一条对角线分成两个三角形。

- `N` 表示对角线从左上连到右下；
- `Z` 表示对角线从左下连到右上。

取走一个三角形有两种可能：

1. 与它在同一格子中的另一个三角形已经被取走；
2. 除了同格子的另一个三角形外，其余与它相邻的三角形均已被取走。

对于每个格子，求最少取走多少个三角形，才能使这个格子中的两个三角形都被取走。若无法做到，输出 `-1`。

### 输入格式

第一行两个整数 `R,C`。

接下来 `R` 行，每行一个长度为 `C` 的字符串，只含 `N` 和 `Z`。

### 输出格式

输出 `R` 行，每行 `C` 个整数。第 `i` 行第 `j` 个数表示格子 `(i,j)` 的答案。

### 数据范围说明

截图未附正式分档表。赛方 std 的数组按 `R,C≤400` 设置，附件最大数据为 `398×399`。整理版沿用本场的 `400` 上限。

### 最小自测例

输入：

```text
1 1
N
```

输出：

```text
2
```

边界外没有三角形，所以其中一个三角形可以直接取走；随后同格另一个三角形也满足条件。

### 部分分一：小网格状态枚举

每个三角形只有“未取走”和“已取走”两种状态，小网格可以把整个取走状态压成一个二进制数。

从状态 `0` 开始，每次枚举一个尚未取走的三角形，检查它是否满足任意一条规则。若能取走，就转移到新状态。首次让目标格子的两个三角形都被取走时，步数就是答案。

状态数为 `O(2^(2RC))`，只适合 `RC` 极小的数据。它能直接按照题意模拟，也是检验依赖图的好暴力。

### 部分分二：把先取条件建成依赖图

若要在同格另一个三角形尚未取走时取走三角形 `u`，那么与它相邻的若干三角形必须先被取走。把这些先决条件看成有向边：

```text
u -> 必须先于 u 取走的三角形
```

若从目标三角形出发能访问到一个环，就说明这些三角形互相等待，不可能以这种方式开始；否则所需三角形就是目标在依赖图中可达的闭包。

按照 `N/Z` 的几何方向，可以把每个半片连向两个相邻半片。赛方 std 中用 `type=0/1` 区分一个格子的两类三角形。

对每个格子分别尝试两种三角形，做 DFS/BFS 求依赖闭包，若含环则该方向不可行。每个方向独立遍历全图，复杂度约为 `O((RC)^2)`，适合中小网格。

注意：只判断“当前是否无环”还不够。若目标可达的任意部分成环，这种取法也无法完成。

### 满分做法：按行扫描，避免重复计算闭包

赛方题解的关键观察是：同一行中，同方向的三角形会连向前一个同方向三角形。于是不必对每个格子重新跑一遍完整的图遍历。

对第 `i` 行分别进行两次扫描：

1. 从左到右，依次计算以 `type=0` 开始的依赖；
2. 从右到左，依次计算以 `type=1` 开始的依赖。

用 `vis` 记录状态：

- `0`：尚未访问；
- `-1`：当前 DFS 栈中，若再次遇到就说明成环；
- `1`：其依赖已经统计过。

`dfs` 返回这次新增加的三角形数量。若遇到 `vis=1` 的结点，直接返回 `0`，因为它的贡献已经包含在前面的累计值里，不能重复相加。

记：

```text
lef[i][j] = 从左到右扫描到 (i,j) 时的累计依赖数量
rig[i][j] = 从右到左扫描到 (i,j) 时的累计依赖数量
```

每访问一个此前未统计的格子方向，基础贡献为 `2`；越界返回 `0`，成环返回无穷大。最后：

```text
answer[i][j] = min(lef[i][j], rig[i][j])
```

若结果仍为无穷大，输出 `-1`。

这里“已经统计过的结点返回 `0`”是整份代码最容易误读的地方：它不是漏算，而是配合 `lef/rig` 的累计和去重。

### 复杂度

对每一行，每个三角形状态在两次扫描中只会产生常数次有效扩展。设 `V=RC`：

- 时间复杂度 `O(RC)`；
- 空间复杂度 `O(RC)`；
- 按赛方 std 的写法，若网格是 `n×n`，也可理解为每行 `O(n^2)`，总计 `O(n^3)`。

整理版忠实改写赛方 DFS，并把输入输出文件从 `cake.in/out` 改回 `grid.in/out`。

### 代码文件

- 我的赛时代码：`grid/contest.cpp`，采用队列删格模拟；
- 赛方原始代码：`grid/source.cpp`；
- 整理版：`grid/solution.cpp`。

## T4 环路 `loop`

原题：P7833，CCO 2021 Day 2 T3 Loop Town。原题时间限制 4 秒，满分 25 分。

### 题面

环形道路周长为 `L`，环上有 `n` 个起点和 `n` 个终点，所有 `2n` 个位置互不相同。

第 `i` 个人从位置 `a_i` 前往位置 `b_i`，可以选择顺时针或逆时针行走。需要为每个人选择方向，使所有人路线两两相交的总次数最小。

### 输入格式

第一行两个整数 `n,L`。

接下来 `n` 行，每行两个整数 `a_i,b_i`。

### 输出格式

输出最小的路线相交总次数。

### 数据范围与评分

对于全部数据：

```text
1≤n≤10^6
1≤L≤10^9
0≤a_i,b_i<L
所有 2n 个位置互不相同
```

| 部分分 | 分值 | 限制 |
|---|---:|---|
| 1 | 12 | `n≤5000` |
| 2 | 额外 6 | `n≤100000` |
| 3 | 额外 7 | 无额外限制 |

### 原题样例

#### 样例 1

输入：

```text
3 100
10 50
30 20
60 40
```

输出：

```text
0
```

#### 样例 2

输入：

```text
4 100
30 70
10 12
60 75
90 50
```

输出：

```text
1
```

### 部分分一：枚举方向

`n` 很小时，每个人都有顺、逆时针两种选择，可以枚举 `2^n` 组方向，再按圆弧位置关系计算相交次数。

总复杂度约为 `O(2^n*n^2)`，只适合极小数据。这个做法可以帮助理解题意，但无法进入 `n=5000` 的正式部分分。

### 部分分二：初始包含关系也用平方算法

满分算法中只有“求初始排列的逆序对”必须使用树状数组，后面的 `n` 次循环移位都可以 `O(1)` 更新。

因此在 `n≤5000` 时，可以直接用两重循环求初始逆序对，再使用下文的增量公式。总复杂度 `O(n^2)`，不必实现树状数组。

### 满分做法一：转成排列与圆弧包含

把每个人的起点、终点看成圆上的一段顺时针弧。将所有人按起点位置排序，并记：

```text
p[i] = 第 i 个人的终点在全部终点中的名次
```

`p` 是 `1...n` 的排列，`q[p[i]]=i` 是它的逆排列。

合法终态对应：

```text
p[i] = (i+k) mod n
```

也就是 `p` 的某个循环移位。几何上，这等价于这些圆弧两两不包含。

固定一个循环移位时，最少需要处理的次数等于圆弧之间的包含关系数。其要点是：

- 每次交换只会让相关包含关系数变化至多 `1`；
- 只要仍存在包含关系，就能选出一对进行处理，使总数恰好减少 `1`；
- 因而包含对数既是下界，也可以通过逐步消除达到。

固定移位时的包含对数可写成：

```text
F = contain - dif + pos*(n-pos)
```

其中：

```text
contain = p 的逆序对数，即 i<j 且 p[i]>p[j] 的对数
pos     = 满足 p[i]>i 的元素个数
dif     = 2 * 所有 max(p[i]-i,0) 之和
```

于是问题变为：求初始 `contain`，再枚举 `n` 个循环移位，取 `F` 的最小值。

### 满分做法二：循环移位时只做常数更新

假设当前正从第 `t-1` 个移位变成第 `t` 个移位。原来终点名次为 `t` 的人会发生环绕，其起点下标为：

```text
i = q[t]
```

这次变化中：

```text
contain += n - 2*i + 1
```

因为它从当前序列的一端换到另一端，左边 `i-1` 个关系和右边 `n-i` 个关系发生改变，其余关系不变。

维护 `pos` 和 `dif` 时，先把所有仍为正的 `p[i]-i` 减 `1`：

```text
dif -= 2*pos
```

其中恰好从 `1` 变成 `0` 的元素不再计入 `pos`。用 `cnt[d]` 记录当前差值为 `d` 的元素个数，即可批量删除：

```text
pos -= cnt[t]
```

发生环绕的元素若满足 `i<n`，新的差值为 `n-i`，需要重新加入：

```text
pos++
dif += 2*(n-i)
cnt[n-i+t]++
```

最后一个下标 `+t` 是为了让它在未来差值再次减到 `0` 时被删除。因此 `cnt` 的下标可能达到约 `2n`，数组不能只开 `n`。

### 实现步骤

1. 按起点坐标排序所有人的记录；
2. 按终点坐标排序下标，得到排列 `p`；
3. 从右往左扫描 `p`，用树状数组求初始逆序对数 `contain`；
4. 同时建立逆排列 `q`，初始化 `pos、dif、cnt`；
5. 枚举 `n` 个移位，更新答案并按上述公式维护四个量；
6. 输出最小值。

坐标值本身只用于排序，所以 `L≤10^9` 不会造成数组建模问题。

### 复杂度

- 排序与初始逆序对：`O(n log n)`；
- 枚举全部循环移位：`O(n)`；
- 总时间复杂度 `O(n log n)`，空间复杂度 `O(n)`；
- `contain、dif` 和答案都可能达到平方级，必须使用 64 位整数。
