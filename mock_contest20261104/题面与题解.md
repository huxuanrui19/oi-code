## T1 排列 `arrange`

原题：P7972，KSN2021 Self Permutation。原题时间限制 2 秒，空间限制 256 MB，满分为 100 分。

### 题面

给定一个长度为 `n` 的排列 `a`。每次可以选择两个相邻的数，删除其中较大的那个。

删除后，左右两部分会拼接起来，原来不相邻的数可能因此变得相邻。问进行若干次操作后，最终可能得到多少种不同的非空序列。答案对 `1e9+7` 取模。

### 输入格式

第一行一个整数 `n`。

第二行 `n` 个整数，表示排列 `a`。

### 输出格式

输出一个整数，表示最终可能得到的序列数量模 `1e9+7`。

### 数据范围

对于全部数据，`1≤n≤3×10^5`，`a` 是 `1...n` 的排列。

原题有特殊小样例、`n≤200` 等部分分；这里重点写可递进的通用做法，而不是只针对某一个固定样例。

### 原题样例

#### 样例 1

输入：

```text
3
2 3 1
```

输出：

```text
3
```

三种结果为 `[2,3,1]`、`[2,1]`、`[1]`。

#### 样例 2

输入：

```text
4
2 1 4 3
```

输出：

```text
6
```

### 部分分一：枚举保留集合

`n` 很小时，可以枚举最终保留哪些位置，再检查中间被删去的数是否真的能删干净。

因为原数组是排列，不同保留位置对应不同序列，不需要再去重。直接枚举所有子集需要 `O(2^n)` 个状态，检查一个状态还需要 `O(n)`，只适合非常小的数据。

这个做法的价值是：可以把“操作过程”转化为“保留下来的子序列是否合法”。

### 部分分二：按结尾做 DP

设 `f[i]` 表示以原位置 `i` 结尾的合法序列数量。这里的“合法”只要求 `i` 之前的数能按规则处理，暂不删除 `i` 后面的后缀。

如果序列只保留 `i`，那么 `i` 前面的所有数必须能删空；否则设倒数第二个保留位置为 `j`，需要先删空 `(j,i)`，再把前面的合法序列接到 `a[i]` 后面。

核心判定如下。

> 对 `l<r`，`(l,r)` 中的数能被全部删除、同时保留 `a[l]` 和 `a[r]`，当且仅当
>
> `min(a[l],a[l+1],...,a[r]) = min(a[l],a[r])`。

原因是：

- 如果最小值在内部，两个保留的端点把它与外界隔开，它不可能遇到比自己更小的数；
- 如果最小值就是某个端点，那么从这个端点向内扫，依次让它删除紧挨着的内部元素，到另一个端点前停下；两个端点都保留。

因此有转移：

```text
f[i] = 单独保留 i 的方案数
     + 所有满足 (j,i) 可删空的 f[j] 之和
```

直接枚举 `j` 并维护区间最小值，复杂度 `O(n^2)`；若每个区间都重新求最小值，则是 `O(n^3)`。`O(n^2)` 已能处理 `n≤200` 的部分分。

最后，只有 `a[i]` 是后缀最小值时，`i` 后面的数才能全部删除，所以答案是所有后缀最小值位置上的 `f[i]` 之和。

### 满分做法：用前驱、后继重写转移条件

直接枚举 `j` 的瓶颈是判断 `(j,i)` 能否删空。定义：

```text
pre[i] = i 左边最近的、数值小于 a[i] 的位置；不存在则为 0
nxt[i] = i 右边最近的、数值小于 a[i] 的位置；不存在则为 n+1
```

由于输入是排列，不存在相等值。

对于 `j<i`，可以把转移条件统一写成：

```text
nxt[j] > pre[i]
```

若最小值在内部位置 `k`，则 `nxt[j]≤k≤pre[i]`，转移不合法。反之，若左端点最小，则 `nxt[j]>i`；若右端点最小，则 `pre[i]<j`。这两种合法情况都满足 `nxt[j]>pre[i]`。

按位置递增扫描，将已算出的 `f[j]` 存在树状数组的下标 `nxt[j]`（包括哨兵 `n+1`）。这样可以一次取出所有合法前驱：

```text
f[i] = (pre[i] == 0) + sum(n+1) - sum(pre[i])   （取模）
```

第一项单独计数只保留 `i` 的前缀：它可行当且仅当 `a[i]` 是前缀最小值。先查询再更新，保证前驱严格在 `i` 左侧。

### 正确性概括

1. 最终序列一定是原排列的子序列；两个保留位置之间的所有数必须满足区间最小值条件。
2. `f[i]` 枚举倒数第二个保留位置，因此不重不漏地统计所有以 `i` 结尾的合法前缀序列。
3. 前驱、后继条件与区间最小值条件等价，树状数组只是快速求满足条件的 `f[j]` 之和。
4. 答案只统计后缀最小值位置，恰好对应后缀也能删空的情况。

### 复杂度

- 求 `pre`、`nxt`：各 `O(n log n)`；
- DP：`O(n log n)`；
- 空间：`O(n)`。

整理版沿用了赛时代码的树状数组思路，但拆清了函数、补全变量含义，并保留 `dp` 数组用于最后统计答案。

- 赛方原始代码：`arrange/source.cpp`，使用 `set` 维护递减结构；
- 整理版：`arrange/solution.cpp`。

## T2 单词 `word`

本场 G123920 对应 **COCI 2018/2019 第五轮第 4 题 Parametriziran**（[官方英文题面](https://hsin.hr/coci/archive/2018_2019/contest5_tasks.pdf)，[洛谷 P7377](https://www.luogu.com.cn/problem/P7377)）。两份题面的输入和计数对象一致：每一行是一个独立的单词，每个问号可以独立替换，求兼容的无序下标对。

### 题面

字符集由小写英文字母和 `?` 组成。两个等长字符串相似，当且仅当可以把两个串中的每个 `?` 独立替换成任意小写字母，使替换后的两个字符串完全相同。

例如，`a???` 和 `?b?a` 都可以替换成 `abba`，所以它们相似。

给定 `n` 个长度为 `m` 的字符串，求相似的无序字符串对数。同一对只计算一次；输入中可能出现完全相同的字符串。

### 输入格式

第一行两个整数 `n,m`。

接下来 `n` 行，每行一个长度为 `m` 的字符串。

### 输出格式

输出相似字符串的无序对数。

### 数据范围说明

原题为 `1≤n≤50 000`、`1≤m≤6`，时限 3 秒，空间限制 64 MB。30% 的分数满足 `m≤2`，另有 30% 满足 `m≤4`。本场附件三组数据的长度也分别为 2、4、6。

**原题样例 1：** 输入三个长度为 3 的单词 `??b`、`c??`、`c?c`，答案是 `2`。中间的单词能分别匹配另外两个；首尾两个单词的最后一个字母冲突。三组原题样例均已收入验证脚本。

### 自测例

输入：

```text
4 2
a?
?b
ab
cc
```

输出：

```text
3
```

三对为 `(a?, ?b)`、`(a?, ab)`、`(?b, ab)`。这不是附件中的官方样例，只是帮助理解题意的小例子。

### 部分分：两两直接检查

两个字符串相似，当且仅当每个位置都满足下面至少一个条件：

```text
s[k] == '?'
t[k] == '?'
s[k] == t[k]
```

逐对枚举并扫描每一位即可。时间复杂度 `O(n^2*m)`，空间复杂度 `O(n*m)` 或边读边存时的 `O(n*m)`。

这个判断也说明：不需要真的枚举 `?` 的替换字母。两个串能否变得相同，只与每个位置的兼容关系有关。

### 赛时 Trie 做法及其瓶颈

赛时代码建立 27 叉 Trie：26 个小写字母加一个 `?` 分支。依次插入前串、查询当前串，可以正确处理重复串，并且每个无序对只统计一次。

查询时：

- 当前字符为字母：可走相同字母边，也可走对方的 `?` 边；
- 当前字符为 `?`：可走对方的 `?` 边，也可走 26 条字母边。

它的逻辑是正确的，但最坏情况下，每次查询可能遍历 Trie 的大量结点。例如很多字符串都含大量 `?` 时，单串查询就不能视为只走 `O(m)` 条边。因此不能把它直接写成有保证的满分复杂度。

### 满分做法：把“是否兼容”变成“模式是否有交集”

逐对检查慢的原因是同一个串被反复比较。可以把每个串预先展开成若干模式键，再用哈希表统计相同键。

代码使用 `0...25` 表示原字母，并增加两个标记：

- `26`：插入串此处是字母，查询串此处是 `?`；
- `27`：插入串此处是 `?`。

对**要插入哈希表的串 `s`**：

```text
字母 c -> c 或 26
?      -> 27
```

对**正在查询的串 `t`**：

```text
字母 c -> c 或 27
?      -> 26 或 27
```

两个串在某个位置兼容，当且仅当它们在该位置有共同的模式符号；所有位置都兼容，当且仅当它们恰好有一个共同的完整模式键。

逐项验证：

- 两边为相同字母：键 `c` 相遇；
- 两边为不同字母：没有共同键；
- 插入为字母、查询为 `?`：键 `26` 相遇；
- 插入为 `?`、查询为字母：键 `27` 相遇；
- 两边都是 `?`：键 `27` 相遇。

关键是每种兼容情况都只有一个共同符号。逐位取这个唯一符号，整个串就只有一个共同键，因此把命中的桶计数直接相加不会重复。即使两个输入串完全相同，计数单位仍是它们在输入中的下标。

因此每个字母位置在插入和查询时各有两种选择，每个字符串最多产生 `2^m` 个键。

依次处理输入：先查询之前字符串建立的哈希表，再插入当前字符串，保证只统计 `j<i` 的无序对。

### 复杂度

令每个串最多生成 `2^m` 个键：

- 期望时间复杂度 `O(n·2^m)`，依赖散列表操作期望为常数；
- 空间复杂度 `O(n·2^m)`。固定长度的 30 进制键小于 `30^6`，32 位足够；开放寻址表在上限数据开两个长度为 `2^22` 的 32 位数组，共 32 MiB。探测时比较完整键，桶冲突不影响正确性；
- 答案最大为 `1 249 975 000`；实现用 64 位累加，直接计算上界时也应先转为 64 位再乘。

- 赛方原始代码：`word/source.cpp`；
- 整理版：`word/solution.cpp`，使用开放寻址表计数。

## T3 网格图 `grid`

本场题号 **G123921**。目前能核实的是：[本场题面](statement/3.png)和[续页](statement/4.png)使用 `N/Z` 描述对角线；[赛方标程](grid/source.cpp)读写 `cake.in/out`；随题题解也把三角形称为“半片蛋糕”。这些是检索线索，没有注明原比赛或公开题号，暂不把任何同名 Cake 题列作原题。

### 题面

有一张 `R` 行 `C` 列的网格图，每个格子被一条对角线分成两个三角形。

- `N` 表示对角线从左上连到右下；
- `Z` 表示对角线从左下连到右上。

取走一个三角形有两种可能：

1. 与它在同一格子中的另一个三角形已经被取走；
2. 除了同格子的另一个三角形外，其余与它相邻的三角形均已被取走。

对于每个格子，求最少取走多少个三角形，才能使这个格子中的两个三角形都被取走。若无法做到，输出 `-1`。

### 输入格式

第一行两个整数 `R,C`。

接下来 `R` 行，每行一个长度为 `C` 的字符串，只含 `N` 和 `Z`。

### 输出格式

输出 `R` 行，每行 `C` 个整数。第 `i` 行第 `j` 个数表示格子 `(i,j)` 的答案。

### 数据范围说明

截图未附正式分档表。赛方 std 的数组按 `R,C≤400` 设置，附件最大数据为 `398×399`。这可用于确定压力测试规模，不能当作已核实的原题限制。

### 最小自测例

输入：

```text
1 1
N
```

输出：

```text
2
```

边界外没有三角形，所以其中一个三角形可以直接取走；随后同格另一个三角形也满足条件。

### 部分分一：小网格状态枚举

每个三角形只有“未取走”和“已取走”两种状态，小网格可以把整个取走状态压成一个二进制数。

从状态 `0` 开始，每次枚举一个尚未取走的三角形，检查它是否满足任意一条规则。若能取走，就转移到新状态。首次让目标格子的两个三角形都被取走时，步数就是答案。

状态数为 `O(2^(2RC))`，只适合 `RC` 极小的数据。它能直接按照题意模拟，也是检验依赖图的好暴力。

### 从一片的先决条件，推出整格的依赖

只需枚举目标格先取左片还是先取右片。第一片取走后，第二片可立即取走。若第一片 `u` 的某条直角边与邻格的 `v` 相接，则必须先取走 `v`。此时 `u` 尚在，`v` 不可能借助“直角边均已清空”先取，因此邻格只能**先取不与这条边相接的半片，再取 v**。越界的一侧没有依赖。

于是状态 `(格子, 首片)` 表示取完这个格子，首片的两条直角边最多引出两个邻格。下面的“左、右”以三角形所接触的竖边命名：

| 首片 | 水平依赖 | 在 N 格中的竖直依赖 | 在 Z 格中的竖直依赖 |
|---|---|---|---|
| 左片 | 左邻格，左片先取 | 下邻格 | 上邻格 |
| 右片 | 右邻格，右片先取 | 上邻格 | 下邻格 |

竖直邻格也取远离公共边的一片。例如要清空下邻格的上边，若下邻格为 N，则左片先取；为 Z 则右片先取。

每个依赖都由规则强制，所以每个被访问的格子至少要取两片。搜索过程中若回到栈内格子，就要求该格先于自身完成，这个起点无解。否则按依赖的后序取走每格两片，恰能达到上述下界。格子已经取空后，无论从哪个方向再遇到它，都不增加代价。对每个起点单独求解需要 `O((RC)²)` 时间。

### 按行复用搜索结果

固定一行。先取左片的格子总是依赖左邻格先取左片，所以从左到右扫描，前一格的全部工作也是后一格所必需的。保留前面已经取空的格子和累计片数，只搜索本次新增的依赖；若前一格无解，这个方向的后续格子均无解。先取右片则反向扫描。两个方向独立初始化，每个格子取两次结果的较小值，两者都不可行才输出 `-1`。

实现用显式栈记录“当前状态、下一条待处理的边”，按**格子**记录未访问、栈内、已取空三种颜色。长依赖链可能达到网格规模，递归写法会在某些 400×400 棋盘格上耗尽调用栈。

每一行的每个方向最多访问 `RC` 个格子，初始化颜色也要 `O(RC)`。总共做 `2R` 次扫描，故总时间为 **`O(R²C)`**，正方形时为 `O(n³)`；边表、颜色和栈共用 **`O(RC)`** 空间。

- 我的赛时代码：`grid/contest.cpp`，采用队列删格模拟；
- 赛方原始代码：`grid/source.cpp`；
- 整理版：`grid/solution.cpp`。

## T4 环路 `loop`

原题：P7833，CCO 2021 Day 2 T3 Loop Town。原题时间限制 4 秒，满分 25 分。

### 题面

环形道路周长为 `L`，环上有 `n` 个起点和 `n` 个终点，所有 `2n` 个位置互不相同。

所有人同时出发，第 `i` 个人从 `a_i` 走到 `b_i`；先到的人要在门口等最后一人到达。求两个人在路上互相穿过的最少总次数。仅仅走过同一段路不算穿过；关键是人在环上的相对次序是否交换。见 [CCO 官方题面，Day 2 Problem 3](https://cemc.uwaterloo.ca/sites/default/files/documents/2021/2021CCOProblemSet.html)。

### 输入格式

第一行两个整数 `n,L`。

接下来 `n` 行，每行两个整数 `a_i,b_i`。

### 输出格式

输出最少的人员交叉次数。

### 数据范围与评分

对于全部数据：

```text
1≤n≤10^6
1≤L≤10^9
0≤a_i,b_i<L
所有 2n 个位置互不相同
```

| 部分分 | 分值 | 限制 |
|---|---:|---|
| 1 | 12 | `n≤5000` |
| 2 | 额外 6 | `n≤100000` |
| 3 | 额外 7 | 无额外限制 |

### 原题样例

#### 样例 1

输入：

```text
3 100
10 50
30 20
60 40
```

输出：

```text
0
```

#### 样例 2

输入：

```text
4 100
30 70
10 12
60 75
90 50
```

输出：

```text
1
```

### 小规模：环上相邻交换

一次穿过交换两个相邻行人的环上顺序。反过来，任意一次相邻交换都能由这两人局部交叉实现；达到终点的循环顺序后，大家可以保持顺序走到各自的终点。因而只需知道起点和终点各自的顺序。小规模时，从目标顺序的所有循环移位一起做 BFS，边为环上任意相邻位置的交换（包括首尾），就能得到最少次数。

### 部分分二：初始包含关系也用平方算法

满分算法中只有“求初始排列的逆序对”必须使用树状数组，后面的 `n` 次循环移位都可以 `O(1)` 更新。

因此在 `n≤5000` 时，可以直接用两重循环求初始逆序对，再使用下文的增量公式。总复杂度 `O(n^2)`，不必实现树状数组。

### 满分做法一：转成排列与圆弧包含

给起点按坐标从小到大编号，再将这些编号按终点坐标排序。`p[i]` 是**终点排名第 i 的人的起点排名**，`q[p[i]]=i`。交换可以倒放，故从终态排回初态与正向的最少次数相同。目标是任意循环有序的排列，例如 `[3,4,1,2]` 已经不需要交换。

沿用赛方题解的圆弧计数结论：在排名圆上连接位置和对应值，对值编号枚举所有循环移位，取圆弧包含对数的最小值。固定编号时，相邻起点之间的一次交换至多消除一对包含；存在包含时，可以选取相邻的嵌套弧来消去一对。固定一种编号的计数可能偏大，故还必须枚举移位。这里的弧是**排名的辅助表示**，并非行人实际覆盖的路段。

固定移位时的包含对数可写成：

```text
F = contain - dif + pos*(n-pos)
```

其中：

```text
contain = p 的逆序对数，即 i<j 且 p[i]>p[j] 的对数
pos     = 满足 p[i]>i 的元素个数
dif     = 2 * 所有 max(p[i]-i,0) 之和
```

于是问题变为：求初始 `contain`，再枚举 `n` 个循环移位，取 `F` 的最小值。

### 满分做法二：循环移位时只做常数更新

假设当前正从第 `t-1` 个移位变成第 `t` 个移位。每个值减一，并将 0 变回 n。初始值为 `t` 的元素在这一步从 1 变成 n，其位置为：

```text
i = q[t]
```

这次变化中：

```text
contain += n - 2*i + 1
```

因为它从当前序列的一端换到另一端，左边 `i-1` 个关系和右边 `n-i` 个关系发生改变，其余关系不变。

维护 `pos` 和 `dif` 时，先把所有仍为正的 `p[i]-i` 减 `1`：

```text
dif -= 2*pos
```

其中恰好从 `1` 变成 `0` 的元素不再计入 `pos`。用 `cnt[t]` 记录在第 `t` 次移位时差值将降到零的元素个数，即可批量删除：

```text
pos -= cnt[t]
```

发生环绕的元素若满足 `i<n`，新的差值为 `n-i`，需要重新加入：

```text
pos++
dif += 2*(n-i)
cnt[n-i+t]++
```

最后一个下标 `+t` 是为了让它在未来差值再次减到 `0` 时被删除。因此 `cnt` 的下标可能达到约 `2n`，数组不能只开 `n`。

### 实现步骤

1. 按起点坐标排序所有人的记录；
2. 按终点坐标排序下标，得到排列 `p`；
3. 从右往左扫描 `p`，用树状数组求初始逆序对数 `contain`；
4. 同时建立逆排列 `q`，初始化 `pos、dif、cnt`；
5. 枚举 `n` 个移位，更新答案并按上述公式维护四个量；
6. 输出最小值。

坐标值本身只用于排序，所以 `L≤10^9` 不会造成数组建模问题。

### 复杂度

- 排序与初始逆序对：`O(n log n)`；
- 枚举全部循环移位：`O(n)`；
- 总时间复杂度 `O(n log n)`，空间复杂度 `O(n)`；
- `contain、dif` 和答案都可能达到平方级，必须使用 64 位整数。
