## A. 消消乐（erase）

### 题意

给一个只含 `A`、`B`、`C` 的字符串，每次操作可以：

1. 找一个 `A`，删除它和它**后面**的某个 `B`（`AB` 消去）；
2. 找一个 `B`，删除它和它**后面**的某个 `C`（`BC` 消去）。

每次操作恰好删掉一个 B。求最多操作次数。

### 样例

输入 `AACCBABBCB`（含 4 个 B），输出 `4`：每次操作恰好删掉一个 B，所以操作数最多 4；而 4 确实可以达到（例如先消两组 `AB` 再消一组 `BC`、再消一组 `AB`），答案取到上限。

### 思路

官方题解的视角：**把操作看成"给一个 B 找搭档"**——每个 B 要么匹配它前面的一个 A，要么匹配它后面的一个 C，每个 B 至多匹配一次。

- 能匹配就匹配一定最优（交换论证：匹配让剩余字符靠得更近，不会破坏后续匹配机会）；
- 越靠后的 B，前面累计的 A 越多；越靠前的 B，后面的 C 越多，所以**优先匹配 C，且优先匹配离它近的 C**（近的先失效）。

标程用两次独立扫描实现：

1. **从左往右**：维护可用 A 数 `cnt`，遇到 B 且 `cnt > 0` 就配对（`ans++`）；
2. **从右往左**：维护可用 C 数，遇到 B 就配对（`ans++`）。

最后输出 `min(ans, tot)`：`tot` 是 B 的总数（操作数上限，每次操作恰删一个 B）；两次扫描独立，同一个 B 可能被两边各匹配一次导致 `ans` 重复计数，`min` 截掉重复。

```cpp
for(int i = 0; i < (int)str.size(); i++){
    if(str[i] == 'A') cnt++;
    if(str[i] == 'B' && cnt) cnt--, ans++;
    if(str[i] == 'B') tot++;
}
cnt = 0;
for(int i = (int)str.size() - 1; i >= 0; i--){
    if(str[i] == 'C') cnt++;
    if(str[i] == 'B' && cnt) cnt--, ans++;
}
cout << min(ans, tot);
```

### 关键点

- 复杂度 O(|s|)。
- "上限取 min"是处理重复计数的常见收尾手法。

### 我的赛时代码点评（erase.cpp）

用 deque 存所有 B 的下标：先扫 C、从队首弹最近的 B 匹配，再扫 A 匹配剩下的。思路与官方一致（优先 C、就近匹配），且每个 B 只会被弹一次，天然不重复计数，比标程的 `min(ans, tot)` 更干净。**写法正确。**

## B. 修路（upkeep）

### 题意

n 个点 m 条无向边，每条边有**长度 l** 和**代价 c**。选一些边修建，要求：

> 修建后得到的新图中，**任意两点间的最短路长度不超过原图中的最短路长度**。

在此前提下最小化总代价，输出最小总代价。

（这个题意是我从标程反推后，用子集枚举暴力对拍确认过的：标程的输出 = "保持全源最短路不变" 的最小代价子集。）

### 数据范围

n, m ≤ 2000，l、c 在 long long 范围。样例第一行 `500 2000`，随后 m 行 `u v l c`。

### 部分分：全是 0 长度边

若所有边 l = 0，"最短路不超过原图" 退化为"这些边把图连通"（0 长度路随意走），于是问题变成 **MST**，Kruskal 直接做。

> 我的 upkeep.cpp 只写了这一种特殊情况（按连通块各跑一次 Kruskal）。
> ⚠️ 代码还有个输出 bug：非全零分支里 `cout << ans` 写了两次（第 88 行和第 90 行），会输出两遍答案。

### 正解

把边分两类：

1. **l = 0 的边**：先对它们按 c 跑 Kruskal。同一连通块内的点在后续视为一个点（块内距离已为 0，且付出了最小代价），代价计入答案。
2. **l > 0 的边**：按 **(l, c) 双关键字升序**逐条考虑。设当前已建图为 G，若 `l < dist_G(u, v)`（u、v 指所属连通块的根），这条边**必须修**（答案 += c，边加入 G）；否则这条边**一定没用**，跳过。

```cpp
for(int t = 1; t <= cnt; t++){
    int pos = 0;                       // 未处理边中 (l, c) 最小的一条
    for(int i = 1; i <= m; i++) if(!chosen[i]){
        if(!pos) pos = i;
        else if(Len[i] < Len[pos]) pos = i;
        else if(Len[i] == Len[pos] && Cost[i] < Cost[pos]) pos = i;
    }
    chosen[pos] = true;
    int nu = find(U[pos]), nv = find(V[pos]);
    if(Len[pos] < getdis(nu, nv)){     // 现有最短路比它长 → 必须修
        G[nu].push_back(make_pair(nv, Len[pos]));
        G[nv].push_back(make_pair(nu, Len[pos]));
        Ans += Cost[pos];
    }
}
```

### 正确性（官方题解的交换论证）

- **"没用"的边真的没用**：处理到 e = (u, v, l, c) 时已有 dist_G(u,v) ≤ l。G 中只加过 l' ≤ l 的边，dist 之后只会变小不会变大，e 永远不可能成为让某对点变近的必要边。
- **"有用"的边必须修**：dist_G(u,v) > l 说明现有网络连通 u, v 的路全由更短的边组成、长度却还不够 l。任何合法方案都得让 u, v 间存在长度 ≤ l 的路；而 e 是当前 (l, c) 字典序最小且能缩短这条路的选择，把方案里更贵的选择换成 e 不会变劣。

### 复杂度

瓶颈是每条正边一次最短路：O(m · (n + m) log n)。n, m ≤ 2000 随便过。标程用线段树堆优化 Dijkstra，改写版（`restyled/B.cpp`）换成普通 priority_queue Dijkstra，等价且更好写。

## C. 子序列（subseq）

### 题意

给定长度为 n 的序列 a（1 ≤ a_i ≤ L ≤ 20），q 次询问，每次问区间 [l, r] 内**非降子序列**（值单调不下降）的个数，**包括空子序列**，对 10⁹+7 取模。

（题意同样经过对拍确认：标程输出 = 区间非降子序列数 + 1（空序列）。）

### 数据范围

n ≤ 5×10⁴，L ≤ 20，q ≤ 2×10⁵。

### 我的赛时代码点评（subseq.cpp）

对每个不同的左端点 l，暴力扫右端点维护 `dp[t]` = 以值 t 结尾的方案数，O(Σ(r−l)·L)，最坏 O(n²L)。`maxn[l]` 剪枝（只扫到该 l 出现的最远 r）是好习惯，但救不了复杂度，只能过小数据。

### 正解（标程）：按 (min, max) 计数 + CDQ 分治

本题最值学习的一点：**不按题面定义直接计数，换一个"可合并"的计数对象。**

**不直接数非降子序列，先数所有子集。** 设 `pre[i][j][k]` = 区间 [i, mid] 中，最小值为 j、最大值为 k 的**子集**个数。从 i+1 推到 i：

```cpp
pre[i][j][k] = pre[i+1][j][k];                     // 不选 a[i]
addmod(pre[i][a[i]][a[i]], 1);                     // 单选 a[i]
for(int k = a[i]; k <= L; k++)
    for(int p = k; p <= L; p++)
        addmod(pre[i][a[i]][p], pre[i+1][k][p]);   // a[i] 接在 min=k 的集合前，成为新最小值
```

`suf[i][j][k]`（区间 [mid+1, i]，向后扩展）对称：a[i] 接在 max=p ≤ a[i] 的集合后，成为新最大值。

**为什么这恰好等于非降子序列？** CDQ 递归保证任意两个位置 p < q 总会在某层 mid 被分到两边（p ≤ mid < q）。一个子序列被计入答案，当且仅当在**每一层**分界处"左半最大值 ≤ 右半最小值"；对所有相邻元素对成立 ⟺ 整个序列值单调不下降。每层把询问三分类（全左 / 全右 / 横跨），每个合法子序列恰好被数一次。

**横跨 mid 的询问 [l, r]**，答案是三部分之和：

1. 完全在左半：Σ pre[l][i][j]（1 ≤ i ≤ j ≤ L）
2. 完全在右半：Σ suf[r][i][j]
3. 横跨：左半任取（记其最大值 j）× 右半任取（记其最小值 k），要求 j ≤ k：`Σ_{j≤k} s1[l][j]·s2[r][k]`

其中 `s1[i][k] = Σ_j pre[i][j][k]`（区间 [i,mid] 内最大值恰为 k 的集合数），`s2` 同理。第 3 项是 21×21 的小求和，O(L²)。

```cpp
for(int j = 1; j <= L; j++)
    for(int k = j; k <= L; k++){
        addmod(ans[w.id], pre[w.l][j][k]);
        addmod(ans[w.id], suf[w.r][j][k]);
    }
for(int j = 0; j <= L; j++)
    for(int k = j; k <= L; k++)
        addmod(ans[w.id], (int)((ll)s1[w.l][j] * s2[w.r][k] % MOD));
```

不横跨的询问丢给左右递归。

### 另一个视角（官方题解）

把 dp 状态设计成"处理完前 i 个数、最后一个数是 x"，一次插入相当于乘一个 L×L 转移矩阵；询问变成**区间矩阵乘积的一行求和**，同样 CDQ 解决。标程的 (min, max) 写法避开矩阵，常数更小、也更好写。

### 复杂度

每层：预处理 pre/suf 各 O(L²·len)，合并 O(L²·len + 横跨询问数)。总复杂度 **O((L³·n + q) log n)**，L = 20 时约 8×10³·n·log n，稳过。

### 易错点

- 每轮清空 `pre[mid+1]`、`suf[mid]` 两行及所有 s1/s2 行，memset 范围别写错；
- 空子序列：输出 `(ans + 1) % MOD`，+1 别丢；
- `s1·s2` 乘积先转 long long 再取模。

## D. cookoff

### 题意

两类菜：A 类 n 道、B 类 m 道，**每类都必须按给定顺序全部做完**，两类之间可任意交错。第 i 道 A 菜耗时 a[i]、截止时间 s[i]、得分 p[i]（做完时刻 ≤ 截止时间才得分）；B 菜同理（b[j], t[j], q[j]）。做菜累计用时 = 已做完所有菜的耗时之和。求最大总得分。

### 数据范围

n, m ≤ 10⁶，所有数值 long long。样例 3 的输入有 11 MB，O(nm) 完全不可行。

### 暴力 DP（我的赛时代码 cookoff.cpp）

`dp[i][j]` = 做完 i 道 A、j 道 B 的最大得分：

```
dp[i][j] = max(
    dp[i-1][j] + p[i] · [sa[i]+sb[j] ≤ s[i]],     // 这一时刻做 A_i
    dp[i][j-1] + q[j] · [sa[i]+sb[j] ≤ t[j]]      // 这一时刻做 B_j
)
```

sa、sb 是耗时前缀和；做完 A_i 的时刻是 sa[i]+sb[j]，不晚于 s[i] 就得分。模型本身正确（已对拍验证），但 O(nm) 太大；代码只特判了"所有截止时间相同"的特殊情况，且 dp 数组开的是 2×10³²，遇到大数据直接 RE。

### 正解：DP 压成一维 + 线段树复合懒标记

固定 i，把 dp 值按 j 排成一行，观察转移结构：

**① 行内展开。** 把第二项不断代入展开：

```
dp[i][x] = max over y ≤ x of ( base_i[y] + Σ_{y<k≤x} q[k]·cond_k(i) )
```

其中 `cond_k(i)` = [sa[i]+sb[k] ≤ t[k]]（B_k 在第 i 行做能否得分），`base_i[y]` = 从 (i−1, y) 转移来的值（含 A 得分）。

**② 技巧：q 的前缀和预扣，把"跨 gap 得分"变成"位置折扣"。** 对每个位置 y 预扣 Σ_{k≤y} q[k]——实现上就是对每个 k 做一次后缀区间加 −q[k]（区间 [k, m]）。之后树上位置 y 的储值 = 真实 dp 值 − Σ_{k≤y} q[k]·cond_k(i)。由于折扣也是"前缀和"形式，从源点 y 推进到 x 时，相对在 x 原生决策恰好白赚 `Σ_{y<k≤x} q[k]·cond_k(i)`——**行内转移因此退化为纯前缀 checkmax**。

**③ 得分开关：临界行撤回。** `cond_k(i)` 随 i 增大从真变假，临界行 `t_k = min{ i : sa[i] > t[k]−sb[k] }` 用 upper_bound 预处理；到第 t_k 行时区间加 +q[k] 抵消预扣（此后 cond 恒为假，q[k] 不该再出现）。注意预处理在开头对**所有行**统一做，按 t_k 挂桶，扫行时顺手加回。

**④ 行间转移 = 前缀区间加。** A_i 的得分条件 sa[i]+sb[j] ≤ s[i] 对所有 j ≤ τ_i 成立（τ_i = upper_bound(sb, s[i]−sa[i]) − 1），就是一次前缀区间加 p[i]。

**⑤ 前缀 checkmax 的懒标记。** 这是本题最精妙的点：每个节点一个 `mark`，pushdown 时右儿子对**左儿子当前的**最大值取 max，并继承 mark：

```cpp
void pushdown(int o){
    apply(o << 1, lzadd[o], lztag[o]);
    apply(o << 1 | 1, lzadd[o], lztag[o]);
    lzadd[o] = 0;
    lztag[o] = -INF;
    if(mark[o]){
        mark[o << 1] = mark[o << 1 | 1] = true;
        mark[o] = false;
        apply(o << 1 | 1, 0, tr[o << 1]);   // 右子树对左子树当前 max 取 max
    }
}
```

`apply(o, v, M)` 是"先加 v 再与 M 取 max"的复合标记（懒标记同步复合），一套标记同时支持区间加和前缀 chmax。

主流程：

```cpp
for(int j = 1; j <= m; j++){
    range_add(1, 0, m, j, m, -Q[j]);                  // ② 预扣 q 前缀和
    int t = upper_bound(A, A + n + 1, T[j] - B[j]) - A;
    pos[t].push_back(j);                              // ③ 临界行挂桶
}
for(int i = 0; i <= n; i++){
    for(int j = 0; j < (int)pos[i].size(); j++)
        range_add(1, 0, m, pos[i][j], m, Q[pos[i][j]]);
    mark[1] = true;                                   // ⑤ 本行做前缀 checkmax
    if(i != n){
        int t = upper_bound(B, B + m + 1, S[i + 1] - A[i + 1]) - B - 1;
        if(t >= 0) range_add(1, 0, m, 0, t, P[i + 1]); // ④ 行间前缀加
    }
}
for(int j = 0; j < (int)pos[n + 1].size(); j++)
    range_add(1, 0, m, pos[n + 1][j], m, Q[pos[n + 1][j]]);
cout << query(1, 0, m, m);                            // 单点查 dp[n][m]
```

**不变量**（逐行追踪验证过）：处理完第 i 行后，树上位置 x 的储值 = dp[i+1][x] − Σ_{k≤x} q[k]·cond_k(i)。最后一行结束后所有 cond 全部失效（t_k ≤ n+1 的都在收尾循环里撤回），折扣清零，单点查询位置 m 即得 dp[n][m]。

### 复杂度

O((n + m) log m)，10⁶ 规模稳过。

### 易错点

- 二分基于**前缀和**数组 A、B（自带 A[0]=B[0]=0），右端点写 `A+n+1`（含下标 0），别漏；
- `mark[1] = true` 直接打在根上、不急着下传——靠 pushdown 惰性传播（先打标记、后有区间加时，`tr[左]` 是加完之后的值，传播才正确）；
- 答案是**位置 m 的单点查询**，不是全局最大值；
- lazy 标记是复合标记（加 + chmax），下传顺序和复合规则不能写反。

## 总结与收获

1. **A 题**：贪心要会写交换论证；"上限取 min"是处理重复计数的常见收尾。
2. **B 题**："最短路保持"类约束下，按长度升序逐条判"是否缩短最短路"是经典贪心范式（MST 思想的推广）；输出语句复制粘贴前要检查，别打两遍。
3. **C 题**：**"不按题面定义计数，换一个可合并的计数方式"**——按 (min, max) 数子集 + CDQ 分界恰好刻画单调性，是最值得记住的套路；"区间查询子序列计数"的通用框架是区间矩阵积 + 分治。
4. **D 题**：DP 优化三板斧本场凑齐——**压维**（滚掉一维）、**条件判断转区间加**（二分 + 前缀和预扣）、**取 max 转移转懒标记**（前缀 checkmax，pushdown 时左贡献右）。懒标记不止"加/覆盖/chmax"三种基本款，还可以是依赖兄弟信息的复合标记。
5. 比赛策略：C、D 的暴力分（O(n²L) 和 O(nm) 特判）应该先稳拿，再冲正解。

### 推荐练习

- 线段树懒标记：洛谷 P3372 / P3373【模板】线段树 1 / 2，以及搜索"区间 chmax 懒标记"类题目（如 CF 上的 segment-tree-beats 入门题）。
